## How do I fill an array?

When the items are known, write an array literal. The literal has two forms.
`([] a b c)` takes the element type from the items. `([] _:T (a b c))` states
the type, and the marker `_:T` must be followed by a group in parentheses.

<TargetOutput example={ex("faq/array-literal")} targets={model.generated.targets} />

The compiler knows the number of items, so the target code holds one
statement: `[1, 2, 3, 4, 5]` in JavaScript, `[]int64 {…}` in Go and `vec![…]`
in Rust.

## How do I build an array while the program runs?

When the items come from a loop, from a file or from a calculation, the number
of them is not known in advance. Use the operators that change the array.

| Operator | Function |
| --- | --- |
| `push` | Add an item to the end. |
| `set_at` | Replace the item at an index. |
| `remove_index` | Remove the item at an index. |
| `removeLast` | Remove the last item. |
| `clear` | Remove every item. |
| `insert` | Add an item at an index. Not Java, not C# and not Scala. |

<TargetOutput example={ex("faq/array-mutation")} targets={model.generated.targets} />

The [array operators](/Ranger/docs/reference/operators/array/) page holds the
complete set, and each entry states which targets it writes code for. Note the
two names that do the same work: `remove_index` writes code for every target,
and `remove` writes code for JavaScript only.

## How do I write "not"?

The operator is `!`, and it is in prefix form like every other operator:
`(! value)`. The argument is a boolean.

## How do I create a singleton class?

A singleton class has one instance, and each part of the program uses that
instance. Add the annotation `@singleton(true)` to the class. The compiler then
writes a static function `__singleton()`, and each call gives the same
instance.

<TargetOutput example={ex("faq/singleton")} targets={model.generated.targets} />

The instance is per target process. The compiler writes the registry that the
target language needs, so the program does not hold a global variable.

## How do I write an object to JSON and read it back?

Add the annotation `@serialize(true)` to the class. The compiler then writes
`toDictionary()` and the static `fromDictionary()`.

<TargetOutput example={ex("faq/serialize")} targets={model.generated.targets} />

Two rules apply:

- Every class that the serialized class refers to must also be
  `@serialize(true)`, or it must hold `toDictionary` and `fromDictionary` by
  hand. The compiler stops with the name of the class that is not serializable.
- The generated code uses the JSON operators. The tabs above show which targets
  have them.

## Which annotations change the code for C++, Rust and Swift?

Most targets collect the memory that a program does not use. C++, Rust and
Swift count references instead, and two objects that hold each other keep each
other alive. Ranger has four annotations for this: `weak`, `strong`, `lives`
and `temp`.

The program below is the case that matters: a parent holds a child, and the
child holds the parent back. The back reference carries `@(weak)`.

<TargetOutput example={ex("faq/annotations-memory")} targets={model.generated.targets} />

This is what the three targets do with that annotation. The statements come
from the output above and from the writers of the compiler. A tab holds the
main function, and the class with the two fields is in the complete file behind
the link under the code.

### C++

```cpp
std::shared_ptr<Node> child;
r_weak<Node> parent;
```

`r_weak<T>` is a small wrapper that the compiler writes above the classes. It
holds a `std::weak_ptr<T>` and gives the shared pointer back at the read, so a
field access, a null test and an assignment stay as they were.

The measurement is a leak check. A parent and a child that hold each other with
strong references, built with `g++ -fsanitize=address`, reports
`168 byte(s) leaked in 3 allocation(s)`. With `@(weak)` on the back reference
the same program leaks nothing.

### Swift

```swift
var child : Node?
weak var parent : Node?
```

ARC then frees the pair. Swift needs two things: the storage must be a `var`,
and the type must be optional. Swift sets a weak reference to nil when the
object goes away. Write `@(weak optional)`, as the example does. A field that
states `weak` without `optional` keeps the strong form, because
`weak var parent : Node` is not Swift that compiles.

### Rust

```rust
child : Option<Box<Node>>,
parent : Option<Weak<RefCell<Node>>>,
```

The Rust writer reads `weak`, and the assignment becomes `Rc::downgrade(…)`.

**The Rust output of that assignment does not compile.** `rustc` rejects the
read of the field, and the `Rc` that `Rc::downgrade` takes is a temporary, so
the weak reference would be empty even if it compiled. The cause is under the
annotation: a Rust class is a plain `struct`, so no `Rc` holds the parent. Do
not use `@(weak)` in a program that must compile for Rust.

### The other three annotations

| Annotation | Measured effect |
| --- | --- |
| `strong` | The target code does not change. |
| `lives` | The target code does not change. The compiler uses the annotation for its own lifetime bookkeeping. |
| `temp` | The target code does not change, for the same reason. |

On a target that collects memory — JavaScript, TypeScript, Java, Kotlin, Dart,
C#, Go, Python, PHP and Scala — none of the four changes the output. The
collector handles a cycle.

[Ownership and lifetime](/Ranger/docs/language/ownership/) states the model
behind these annotations, and the
[memory page](/Ranger/docs/targets/memory/) states what each target writes.

## Why does my call not compile?

Ranger is an s-expression language. A call is `(function argument argument)`,
and a call that gives a value needs its own parentheses.

| Write | Do not write | Why |
| --- | --- | --- |
| `return (this.helper())` | `return this.helper()` | The bare form fails the analysis on every target, and the message names an unrelated method. |
| `def v:int (this.helper())` then `return (v + 0)` | `return (this.helper() + 0)` | The call must be the direct operand of the parentheses. |
| `def recv:T (expr)` then `recv.method()` | `(expr).method()` | A statement must not start with a receiver in parentheses. |
| One statement per line | `{ def c:int 5 return c }` | Two statements on one line is a parse error. |

## What does "Could not find suitable match for the operator node" mean?

The call is to a `defn` macro, and no macro of that name fits the arguments.

A macro declares no types. The compiler selects one by trial. It expands the
body of each macro with that name into the call site and compiles the result.
The first candidate that makes no error wins. The message says that every
candidate made an error.

The errors above the message come from the candidate with the fewest errors.
That candidate is not always the macro that you had in mind. Read the message
together with the bodies on the
[macros page](/Ranger/docs/reference/macros/), and start from the types of your
arguments. `ForEach` is an example: one macro reads an array, and another one
reads a hash map, and only the body states the difference.
