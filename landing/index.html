There is no Silver Bullet.

Ranger is more like golden1. But it's not Magic. It emits ordinary source in the language you already ship: Swift for Apple platforms, Kotlin for Android, JavaScript for the browser.

1) An automated software testing method that compares the actual output of a program against a trusted baseline—known as a “golden file” or “golden master”.

Stay Dry.

Are you maintaining a separate harness to keep logic in multiple platforms in sync? Well, Ranger is the harness. Most programs do not need very complex code, but they need a way to verify the execution against a common logic. If you ever get that situation, then Ranger might just be the thing.

The problem

Native apps
without duplicating the logic

If you build iOS and Android separately, the UI can stay native — SwiftUI on iOS, Compose on Android — but shared business logic often gets implemented twice.

That means two copies of things like:

  • validation
  • pricing and calculations
  • state machines
  • parsers
  • sync rules
  • domain models

The implementations may start out identical, but they can drift as the applications evolve.

What Ranger changes

With Ranger, the shared logic has one source file and is compiled to both Swift and Kotlin. 

shared Ranger source
         |
    +----+----+
    |         |
  Swift     Kotlin
    |         |
 SwiftUI   Compose

The platform UI stays native. Only the logic that should behave the same on both platforms is shared.

No bridge or shared runtime

Ranger generates ordinary Swift and Kotlin source code.

The iOS application calls the generated Swift classes normally. The Android application calls the generated Kotlin classes normally.

There is no JavaScript runtime, cross-language bridge, message protocol or serialization layer between the UI and the shared logic.

Swift

let result = pricing.calculate(order)

Kotlin

val result = pricing.calculate(order)

Both calls can originate from the same Ranger implementation.

One implementation to maintain

If a rule changes, you change it once:

Pricing.rgr
    | compile
Pricing.swift
Pricing.kt

The generated files can be checked into the repository, reviewed in diffs and tested with the normal platform toolchains.

This keeps the part that must stay identical in one place, while leaving the parts that should be platform-specific native.

Native UI. Shared logic. One source of truth.

01 — Python

Closest to the language

This is the file I would keep. Classes are classes. An optional is None. ?? becomes x if x is not None else fallback. A counted loop is for i, v in enumerate(xs). Two names for one object are ordinary Python identity. try / throw is try / except Exception as e / raise Exception("…") and it actually catches. sfn main is def main() plus the if __name__ == "__main__" guard. A lambda that is more than an expression is hoisted to a real def.

It is still not the Python a 3.12 package would start from. There are no type hints, no @dataclass, no enum.Enum, no match / case. A shape is two classes with a _rg_kind string. A Ranger trait copies methods rather than becoming a Protocol. Generics monomorphize to Stack_int. Constructors assign defaults and then overwrite them. You do not get yield, with or a comprehension — a for that pushes is an index loop and append.

02 — JavaScript

The compiler’s own target

This is the language the compiler is written against, and it shows. Sharing is object identity. Arrays are arrays. console.log is console.log. try / throw runs: throw "negative" is legal JavaScript and the catch reads the string. A function value is a function. The playground on this site is this back end, compiled to itself.

It is not 2024 JavaScript you would type by hand. Optional is undefined tested with typeof(x) === "undefined", not x ?? fallback or optional chaining. A shape is classes plus __rg_kind tags. A Ranger Enum is a number. A trait is a mixin. Entry is function __js_main() plus a call, not ESM main. There is no Result. @(weak) is ignored — the cycle is a normal reference and GC collects it.

03 — TypeScript

JavaScript, with types you can read

Same writer as JavaScript, plus annotations and export. That is enough to move it up a notch for anyone who will open the file in an editor. An optional string is string | undefined. A shape gets a union alias (type union_Message = Message_Ping | Message_Text | …) and each case carries a typed __rg_kind literal. Method signatures are real TypeScript. throw "…" still runs, the same as on the JS tab.

The types describe the generated model; they do not make it idiomatic. You still get the typeof / != null ternary instead of ??. You still get Stack_int rather than Stack<T>. There is no Result<T, E>, no discriminated-union switch, no ESM entry. A Ranger Enum is still a number. If you already accept the JavaScript, TypeScript is that file with a type-checker attached — not a second back end.

04 — Dart

Null safety, and a real main

Dart is the closest statically typed file in the study. Optional is T?, unwrap is !, lists are [1, 2, 3]. sfn main is void main(List<String> args) at file scope — the line a Flutter package already has. A function-typed parameter is int Function(int), which is the Dart spelling. try / throw runs: Dart allows throw "negative" and catch (e) reads the string. Sharing is ordinary object identity.

It is not Dart 3. A record Point is a mutable class with public fields, not a Dart 3 record and not final fields. A shape is abstract class union_* plus if (x is Case), not a sealed class / switch. A Ranger Enum is an int. ?? is the ternary (hit != null) ? hit! : "unknown", not hit ?? "unknown". Generics become Stack_int. @(weak) is ignored; the parent pointer is just TreeNode?.

05 — Swift

T?, weak var, and a native enum

Swift is where the typed, reference-counted languages start to look like themselves. Optional is T? and ?? is ??. A parent pointer marked @(weak) is weak var x: T? — the ARC spelling. A Ranger shape becomes a native enum with associated values, which is the file a Swift programmer expects for a closed family. throw now emits func … throws, try at the call site and a small Error type. Two names share one object through the class / ARC model.

A Ranger Enum is still an Int, not a Swift enum. A trait used only as a mixin copies methods; used as a type it can become a protocol, but a field-bearing trait has nowhere to live and is refused. There is no Result. Generics monomorphize. The throws path is writer-checked; this environment has no swiftc, so the study does not claim a compiler-clean binary the way Kotlin does.

06 — Kotlin

Nulls and sealed types a JVM file would keep

Optional is T?. A shape is a sealed interface with implementing classes, which is the Kotlin way to close a family. A function type is (Int) -> Int. throw wraps Exception(msg) — kotlinc accepts it and error_msg is the text you threw. Sharing is ordinary JVM object identity. The Android story on this page is this back end: the same Ranger compiled to Kotlin and called from android.graphics.

A Ranger Enum is an Int, not enum class. Generics become Stack_int. A trait is a mixin unless it is used as a type, in which case it is an interface; a field-bearing one is refused. There is no Result / runCatching story. Empty companion object noise is mostly gone, but the file still reads as a port, not as a Kotlin module you would have started from.

07 — C#

Legal C#, with an odd exception type

The types a C# file wants are here: int?, List<T>, Func<int, int>, an interface for a shape with is tests. Two names share one object. throw runs — the catch sees the message. The TypeScript-engine gate builds this target with Mono mcs and matches Node.

The exception type is ConfigurationErrorsException, which is a legal throw and a strange choice for domain errors. A Ranger Enum is an int. Generics are Stack_int. int is 32-bit, so the same arithmetic that is 53-bit on JavaScript can disagree. A trait is a mixin or an interface; it is not a default-interface-method file you would write today. No record, no Result.

08 — Java

It runs. It is Java 7.

The program compiles, throw wraps IllegalArgumentException, and the catch sees the message. Sharing is ordinary objects. A shape is Object plus instanceof, which is what Java 7 had. One class per file is the layout the writer already commits to.

Everything else is the older language. Optionals box: Integer and null, not Optional<T>. A Ranger Enum is Integer. A function value is a generated LambdaSignature1 class, not a lambda. Generics are Stack_int. There are no records, no sealed types, no var. Usable as a port you can javac; not a file a Java 17 shop would keep without rewriting.

09 — PHP

Around JavaScript, with $ and isset

PHP sits with the dynamic targets. Objects share. An optional is null tested with isset. try / throw is throw new Exception, which is the PHP spelling and runs. The main routine is at the top level of the file, which is how PHP scripts already start. A shape is classes distinguished with get_class.

There was no idiom study folder for PHP, so this rank is from the writer, not from a golden run. Fields are var $x. There are no types. A Ranger Enum is an int. A trait is a mixin, not a PHP trait or interface. Generics are Stack_int. It is closer to “a script that works” than to modern typed PHP 8.

10 — Scala

Option[T] is right; the rest is a port

Optional is the one Scala wants: Option[String], Some(n), Option.empty. A shape dispatch is match / case, which is at least the language’s own keyword. sfn main becomes object AppMain extends App. Those three things are why it sits above Go.

Then the file reminds you it is generated. Control-flow returns ride on a case class ScalaReturnValue(value: Any) extends Exception — a hack, not an error type. The shape cases are ordinary classes, not case class / enum. A Ranger Enum is Int. A trait is a mixin, not a Scala trait. No study folder yet; the rank is from the writer.

11 — Go

Pointers share; optionals do not look like Go

Two names for one object are *T assignment, and that part is honest Go. A function-typed parameter is func(int64) int64, which landed. Methods take a pointer receiver. The file builds and prints the same answers as the other targets. try / throw does catch — as panic / recover.

Optional is *GoNullable, not *T and not (T, bool). A parent pointer is that wrapper, not *TreeNode. A shape is a tagged struct with a tag int and a pointer per case, not error. A Ranger Enum disappears into int64. A trait copies methods; it is not an interface unless you force that spelling. Loops are C-style index for, not range. Do not use try / throw if someone will review the .go as a library — prefer a shape.

12 — C++

It compiles. Almost everything is shared_ptr.

The ownership story is the part that is trying to be C++. A cycle marked @(weak) is weak_ptr / enable_shared_from_this. A Ranger Enum can be enum class when every use fits. A shape is std::variant. A function value is std::function plus a [&] lambda. error_msg after catch now carries the real text. An optional string is no longer a plain std::string that could not tell "" from absent — it is r_optional_primitive<std::string>, and study 11 prints the same answer as every other target. g++ accepts the file.

A record Point is still shared_ptr<Point>, not a value struct, and a read-only object parameter is const shared_ptr<Point>&, not const Point&. Optional is the Ranger helper type, not std::optional. There is no std::expected. Variant payloads that are objects stay in cells. int is 32-bit. You can ship the binary; you would not start a C++17 codebase from this spelling.

13 — Rust

The most honest about memory, the least Rust-like

This is the target the compiler thinks hardest about. A record Point is a struct with i64 fields. A method that only reads is &self and &Point. A class the sharing analysis proves is shared becomes Rc<RefCell<T>>; a @(weak optional) parent is Option<Weak<RefCell<T>>>. Optional is Option<T>. A shape is a real Rust enum and the match is a real match where it can be. Names are snake_case. A behaviour-only Ranger trait is a Rust trait. rustc accepts the file and the answers match the other targets.

It is still not a file a Rust programmer would keep. There is no Result, no ?, no lifetimes, no impl Trait for Type, no iterator adapters. try / throw is a compile error (the catch used to be dropped and the binary died — refusing it is the honest outcome). A field-bearing trait used as a type is also refused. Generics are Stack_int. A Ranger Enum is a real enum only when every use fits; otherwise it is an integer. Map / filter is an index for. The big missing piece is an error type: until Ranger has Result, the Rust will always read as a port of an object language.

Platforms

From a watch to a Raspberry Pi
to a browser tab.

Getting a program to run somewhere takes more than a target language: a build, a host, and a way to talk to the screen and the filesystem. That plumbing is in the repository, written in Ranger, for each of these.

01 — Apple

iOS, iPadOS, watchOS

Swift out, and the build itself is a Ranger program. lib/apple/ invokes xcrun, swiftc, plutil, codesign and simctl directly, straight to an installed, running app — without generating an .xcodeproj or invoking xcodebuild. 151 checks assert the plan it produces, which program with which arguments in which order, and they run on JavaScript, Python, Go, Rust, C++, Java and PHP, on any machine, with no Mac in sight. On a Mac, one command puts the app on the simulator; another puts it on the phone on the cable, finding the device, the signing identity and the provisioning profile rather than asking you to type them.

02 — Android

Kotlin and android.graphics

Kotlin with @JvmField, MutableList and the collection types the JVM expects, using the platform's own types directly. The PowerPoint stack is the demonstration: the same Ranger source drawn with android.graphics on the device and with Java2D on any JVM, so the port can be checked on a build server without a phone. The port itself is a facade, one walk over the display list, and two implementations of an eight-method surface.

03 — Web

Node.js and the browser

ES2015 or TypeScript, ESM or CommonJS, with source maps and a package.json when you ask for one. Node is the compiler's own official host — the playground on this site is the compiler, compiled to JavaScript and running in your tab, which is also the shortest description of what self-hosting buys you.

04 — Desktop

SDL2, GLES2 and native binaries

The game engine's C++ path opens an SDL2 window with a GLES2 present path, gamepad input through SDL GameController, and the engine's own audio synth. The same catalogue of games runs unchanged in a browser tab over a virtual filesystem. Headless builds take a frame count and SDL_VIDEODRIVER=dummy, so the window is optional and the same build runs headlessly in CI.

05 — Single board

Raspberry Pi

A deploy script rsyncs the repository to a Pi 5, compiles the SDL2 + GLES2 host on the device — wasm3 included, so WASM games load from committed modules with no Rust toolchain on the board — and wires an autostart. Or you take the offline aarch64 bundle, which is a terminal build that needs no SDL at all. Develop on the desktop and run the same logic on the hardware — which is what the engine was built for.

06 — Servers and tools

Go, Rust, C++, LLVM

Go and Rust for services, C++ for the fast path, LLVM for a lower-level native compilation path that skips the C++ source step. One compiler primitive runs other programs — run_process_result, which answers exit code, stdout and stderr, takes a working directory and extra environment entries, and passes its arguments as a vector so nothing inside one is ever re-read by a shell. It has a back end on thirteen targets, and the library over it records a dry run instead of executing, which is what makes a build driver testable.

EVG

A layout and rendering engine,
written in the language.

EVG lays out a tree with a substantial CSS feature set — flex, grid, the cascade, @media, TrueType metrics and GPOS kerning — then walks it once and emits flat draw commands: filled rect, border, image quad, text run, push and pop clip. Absolute pixels, colours resolved, no tree and no units left. Everything below that seam knows only about quads, glyph runs and scissor rectangles, which is why the same page comes out of six painters.

CSS layout and cascade

Flex and grid, specificity and the cascade, border radius, shadows, transforms, overflow: hidden as a real clip, and @media blocks that fold a side rail into a bottom bar at 768px — in a PDF as much as on a GPU.

Effects on the GPU

Blur, rotation, sub-pixel shift and the surface ripple behind the top of this page. Each has an oracle — a reference implementation the GPU path is checked against on every push — so an effect cannot quietly stop matching the layout.

And a vectoriser

A bitmap tracer: edge walk, corner detection, curve fitting, colour posterising. It reads a PNG or a JPEG and writes paths — and it is what turned Ranger's own logo into the vector on this page. See the showcase →

Getting started

From zero to Ranger

The language itself is small: compiler/Lang.rgr declares 336 core operator definitions under 207 names, and the generated reference documents 838 operators once the standard library is counted in. The way in is not to read all of that first, and it is not to clone this repository either — this is the compiler, the gallery and their own test corpus, which is what you clone to work on Ranger. To write a program in it, the compiler is an npm package and RangerStarter is a project already built around it.

01

Start from the starter

Node is the compiler's official host and the only thing the compiler itself needs. Nothing is installed globally: ranger-compiler is a dependency of your project, so the compiler your program is compiled with is the one your package.json names. The starter is two source files, a test that fails properly, and a build loop — MIT, so keep what you want and delete the rest. 

git clone https://github.com/terotests/RangerStarter my-app
cd my-app && npm install
npm start

02

Compile it where you are going

One flag decides the target, and the output is ordinary source you read in the diff. Generating Swift does not need Xcode, so the whole matrix compiles on the machine you already have; running it is the target toolchain's business. targets:run executes the three a plain machine has and fails when their output differs — which is the only thing that actually checks a portability claim. 

npm run targets       # all fourteen writers
npm run targets:run   # runs three, and compares
npx rgrc -l=kotlin src/Main.rgr

03

Change one thing

Open src/Main.rgr, change the program, and run it again. The .rgr file stays the source of truth; generated target files are disposable and can always be recreated. 

$EDITOR src/Main.rgr
npm start
npm run targets:run

The output is still ordinary source code, not an opaque artifact. Open it when you are curious, diff two targets when something behaves differently, and run it with the target's normal tools. Edit Ranger; inspect everything.

04

Then the gallery, when you need it

gallery/ here is the corpus: parsers for TypeScript, C++ and JavaScript, a spreadsheet, a PowerPoint stack, a game engine, a chart runtime, a node-graph editor, a Figma reader, and EVG — a CSS layout engine with no browser in it. The starter pulls any of them in as a pinned dependency, and says what that costs before it does: the gallery is AGPL-3.0-or-later while the compiler, the runtime and your own program stay MIT. Clone this repository when you want to read the whole corpus or change the compiler. 

scripts/add-gallery.sh        # the list, and the cost
scripts/add-gallery.sh evg

Reading first: the documentation has install, types, optionals, traits, generics and the operator reference generated from the sources of the commit that published it, and the FAQ it links is the shortest path past the errors that otherwise cost an extra edit–compile cycle. Trying before installing anything: the playground compiles Ranger in your browser with nothing installed. Working with an agent anywhere else: /plugin marketplace add terotests/Ranger installs the same skills the starter carries.

Where it stands today

Ranger is experimental. Target quality varies by language and by feature area, several gallery projects need toolchains you may not have, and you should expect to fix a bug or add a capability now and then. It is stronger as a portable-algorithm compiler and DSL toolchain than as a drop-in replacement for a mainstream application language — and it is used that way, daily, on programs as large as itself.

Ranger — a self-hosting cross-language compiler.
