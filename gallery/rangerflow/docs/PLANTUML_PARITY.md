## What this compares

- **The reading, not the drawing.** PlantUML lays a diagram out its own way
  and has no opinion about RangerFlow's, so comparing positions would measure
  two layouts rather than one reader.
- **Not every diagram equally.** PlantUML annotates its own SVG with the ids
  it used — `class="entity"`, `class="link"`, `class="cluster"`,
  `class="message"` — for the class, description and sequence families, and
  with nothing at all for a mindmap or a Gantt chart. Where there is nothing to
  compare, the check is that the type is read as the type it is, and the table
  says `—` rather than pretending to a tick.
- **`parses` is PlantUML's verdict, not ours.** A file PlantUML rejects and
  RangerFlow reads happily means this reader invented syntax.
- **Notes are counted, not named.** PlantUML gives a note an entity of its own
  under an id it made up (`GMN9`); an id that appears nowhere in the file the
  author wrote is one of those.
- **The vocabularies meet in `tools/plantuml-parity.mjs`.** PlantUML says
  `DESCRIPTION`, RangerFlow says `description`. The translation lives in the
  meter so neither model has to hold the other's spelling.
- **PlantUML is GPL and is never linked.** It is run as a subprocess, fetched
  on demand into `harness/vendor/` and not vendored, and no PlantUML source is
  copied into this repository. See `docs/PLAN_PLANTUML.md` §3.5.
